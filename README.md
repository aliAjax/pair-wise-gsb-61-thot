# 汽车型式认证证据包审阅与补件平台

用于按车型、配置、法规项目和维护版本组织测试报告、部件清单、软件版本及豁免材料的本地认证工作台。

## 技术栈

- Nuxt 3 + TypeScript
- Nuxt UI
- Pinia
- Nuxt Router
- ofetch
- TanStack Query for Vue

## 主要工作区

- `/`：认证项目列表、关键词/状态/机构/风险筛选和项目统计
- `/projects/new`：建立车型、配置、维护版本和软件版本基线
- `/projects/[id]`：证据审阅、法规覆盖、状态流转、版本差异、批量补件和审计
- `/regulations`：按法规分类查看项目证据覆盖
- `/imports`：**离线回网补件对账**（核心工作区）
- `/supplements`：跨项目批量补件
- `/reminders`：证书和证据到期提醒
- `/audit`：跨项目审批时间线与提交包导出

## 离线回网对账规则

审阅人携带离线补件包回网合并时，项目基线可能已被另一位审阅人改动，对账按以下规则处理：

1. **逐项按证据版本比较**：区分安全合并（同基线下文件版本更新）、随包新增、无变化、包更旧保留当前、同版本审阅分歧、基线漂移待重认。
2. **安全合并更新覆盖**：合并后法规覆盖依据当前证据即时重算。
3. **基线变更即失效**：软件基线一变，已有 `accepted/rejected` 结论全部转为 `stale`（保留原结论与原审阅基线），并登记基线漂移冲突，必须在当前基线下重新确认；离线包内基于旧基线的结论不会直接生效。
4. **后到结果不覆盖当前审阅**：同版本结论分歧时默认保留当前结论，登记为未处理的 `review_divergence` 冲突，审阅人可显式改用补件包结论。
5. **确认一次写入**：确认时在同一事务写入证据、覆盖、冲突和审计；传输中途断连只保留已落库行的安全点，重试不重做已确认部分。
6. **失败立即重试**：回网上传失败立即用同一补件包重试（内置样例前两次传输失败）。
7. **重复提交幂等**：同一 `packageId` 复用既有会话，已确认包重复导入不生成第二套审计（审计以 `dedupKey` 去重）。
8. **安全点续做**：对账选择和进度持久化到 `localStorage`，页面重开后从未完成会话继续。
9. **冻结保护**：项目批准时生成独立冻结快照，之后基线、证据、补件与导入全部拒绝写入；导出提交包标明采用的基线、冻结快照和未处理冲突。

内置补件包样例（`data/sample-packages.ts`）分别覆盖：传输失败重试、基线漂移、审阅分歧+确认中途断连、已批准冻结拦截。

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18461`。

## 构建、检查与流程验证

```bash
npm run typecheck
npm run build
npm run verify   # 离线对账/失效/冻结/幂等的端到端逻辑验证（无需浏览器）
```

项目没有后端服务，使用结构化模拟数据，并通过 Pinia 和浏览器 `localStorage` 持久化车型项目、证据状态、版本和审计记录。ofetch 由本地模拟 fetch 适配器承载，TanStack Query 负责项目索引查询和筛选缓存。
