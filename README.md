# 汽车型式认证证据包审阅与补件平台

用于按车型、配置、法规项目和维护版本组织测试报告、部件清单、软件版本及豁免材料的本地认证工作台。

## 技术栈

- Nuxt 3 + TypeScript
- Nuxt UI
- Pinia
- Nuxt Router
- ofetch
- TanStack Query for Vue

## 主要工作区

- `/`：认证项目列表、关键词/状态/机构/风险筛选和项目统计
- `/projects/new`：建立车型、配置、维护版本和软件版本基线
- `/projects/[id]`：证据审阅、法规覆盖、状态流转、版本差异、批量补件和审计
- `/regulations`：按法规分类查看项目证据覆盖
- `/supplements`：跨项目批量补件
- `/reconcile`：离线补件包回网对账（逐项版本比对、基线漂移失效、原子确认、断点续传、冻结保护、对账导出）
- `/reminders`：证书和证据到期提醒
- `/audit`：跨项目审批时间线与提交包导出（标注采用基线与未处理冲突）

## 离线补件回网对账规则

- 导入先按证据**文件版本逐项比较**：网内缺失为「安全新增」，版本更新且基线一致为「安全更新」，采纳后重算对应法规覆盖；文件版本相同且结论一致为「重复提交」。
- **当前审阅优先**：网内审阅时间更晚或版本不旧时，保留当前结果，后到的离线结论不覆盖。
- **软件基线漂移**：补件依据的软件基线与网内当前基线不一致时，离线结论分类为「基线冲突」，只能由当前审阅人按新基线**重新确认（reconfirm）**，不能直接生效；项目自身基线变更时，旧基线上的全部已接受结论自动转为「基线已变待重认」。
- 引用了网内不存在的法规项时挂起为「法规缺失」，需人工核对适用性。
- **确认时一次写入全部变化**（证据、法规覆盖、版本、审计），写入在工作副本上完成、成功后整体落盘；任一校验不过则全部不写。
- **导入失败后用同一补件包重试**，每处理一条即落安全点，已处理部分不重做；重复提交同一补件包复用会话，不生成第二套审计（按 `packageId` 幂等）。
- **已批准项目的冻结快照不可改写**：批准时对证据、版本与基线生成校验值并锁定；补件、编辑、状态流转均被拒绝。审阅可重新打开，活动快照归档为不可改写的历史后另起新版本处理。
- 审计提交包与对账说明均标明**采用的软件/维护基线**与**未处理冲突**（基线漂移证据、待重认项、未完整法规）。
- 对账安全点持久化在浏览器 `localStorage`，页面重开后从上次安全点继续。

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18461`。

## 构建与检查

```bash
npm run typecheck
npm run build
```

项目没有后端服务，使用结构化模拟数据，并通过 Pinia 和浏览器 `localStorage` 持久化车型项目、证据状态、版本和审计记录。ofetch 由本地模拟 fetch 适配器承载，TanStack Query 负责项目索引查询和筛选缓存。
